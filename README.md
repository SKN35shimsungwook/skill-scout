# skill-scout

제 Claude Code 대화 기록을 보고, 제가 자주 하는 작업에 맞는 **스킬·플러그인을 매일 아침 디스코드로 추천받으려고** 만들었습니다.

## 왜 만들었나

Claude Code를 매일 쓰는데, 확인해 보니 설치한 플러그인이 0개였습니다. 공식 마켓에만 플러그인이 300개 넘게 있고 skills.sh 같은 곳에도 스킬이 계속 올라오는데, 무엇이 저한테 맞는지 고르기가 어려워서 그냥 안 쓰고 있었습니다. PDF를 그대로 올리다가 마크다운으로 바꾸면 토큰이 덜 든다는 것도 한참 뒤에 알았습니다. 이런 걸 누가 먼저 알려 주면 좋겠다고 생각해서, 최종 프로젝트(AI 사용 환경 관리 비서)의 "도구 맞춤" 기능을 제 기준으로 먼저 만들어 봤습니다.

## 두 가지 사용 방법

| 메뉴 | 기준 | 언제 |
|---|---|---|
| 💬 상담 | 지금 하려는 작업 | 새 작업 전에 "뭐 챙기면 돼?"라고 물으면 상담팀이 받아서 부서들이 준비물(이미 있는 도구 + 설치 추천)을 챙겨 줍니다 |
| 🏢 아침 점검 | 최근 30일 내 사용 이력 | 매일 아침 8시 자동 실행 → 디스코드 브리핑. 사무실 화면에서 지금 실행도 됩니다 |

상담팀만 Gemini 무료 API를 씁니다(질문 이해·답변 문장). 키가 없거나 한도를 넘으면 단어 매칭으로 대신합니다. 나머지 부서는 규칙 기반이라 토큰을 쓰지 않습니다. Gemini에는 상담 질문과 추천 결과만 보냅니다.

화면은 4차 팀 프로젝트(Langration)의 디자인 규칙(밝은 배경, 검정 버튼, 보라 포인트, 사이드바 메뉴)을 따랐습니다.

## 아침 디스코드 브리핑 구성

매일 아침 8시에 섹션마다 메시지를 따로 보냅니다. 도구 추천 말고는 모두 PC 안의 기록만 읽고, 토큰을 쓰지 않습니다.

| 순서 | 섹션 | 내용 |
|---|---|---|
| 1 | 📂 어제 작업 브리핑 | 어제 Claude 대화별 마지막 요청, 사용 한도·중단으로 끊긴 작업, 남은 할 일, 고친 폴더의 커밋·push 안 한 변경 → **오늘 이어서 할 것** |
| 2 | 🩺 상태 점검 | 메모리에 적힌 마감 D-day(+ `data/deadlines.json`), GitHub Actions 실패, push 안 한 커밋, README에 적힌 배포 앱 응답 |
| 3 | 📊 사용량·습관 팁·업데이트 | 어제 토큰(출력·캐시), 가장 많이 쓴 대화, 습관 팁(긴 대화·PDF 원본 읽기·'간단히' 반복·중단), Claude Code 새 버전 |
| 4 | 🧩 도구 추천 | 아래 부서 흐름 결과 |
| 5 | 📝 지난주 요약 (월요일만) | 대화·요청 수, 많이 한 작업, 저장소별 커밋, 못 끝낸 작업, 대화 정리 추천 (주간회고 재료) |

## 어떻게 동작하나

팀 기획서처럼 다섯 부서가 차례로 일을 넘기는 구조로 만들었습니다. 흐름은 LangGraph로 연결했고, 부서마다 규칙 기반이라 LLM 토큰은 쓰지 않습니다.

```
① 수집기 → ② 점검팀 → ③ 검증팀 ─(통과 후보 부족)→ ② 점검팀 재검토
                                 └(충분)→ ④ 브리핑팀 → ⑤ 상담팀
```

| 부서 | 하는 일 |
|---|---|
| ① 수집기 | 제 대화 기록에서 작업 신호를 세고(원문은 PC 밖으로 안 나감), 공식 플러그인 마켓·Anthropic 스킬·skills.sh에서 후보를 모읍니다 |
| ② 점검팀 | 이미 있는 것은 빼고, 제 작업과 겹치는 정도로 순위를 매겨 4개씩 검증팀에 넘깁니다. 흔한 신호는 가중치를 낮췄습니다(IDF) |
| ③ 검증팀 | GitHub 저장소가 있는지, 보관 처리됐는지, 1년 넘게 방치됐는지, 사용자가 너무 적은지 보고 PASS·경고·실패를 판정합니다. 통과가 모자라면 점검팀에 다음 후보를 요청합니다 |
| ④ 브리핑팀 | 통과한 후보로 브리핑을 쓰고, 전날과 비교해 새로 나온 것을 따로 표시해 디스코드로 보냅니다 |
| ⑤ 상담팀 | 오늘 무엇부터 써 보면 좋을지 한 줄로 정리합니다. 설치는 제가 직접 승인합니다 |

부서마다 진행 상황을 이벤트로 남기고, 2D 오피스 화면이 그 이벤트를 받아 캐릭터를 움직입니다.

## 실행

```bash
pip install -r requirements.txt
cp .env.example .env        # DISCORD_WEBHOOK_URL 입력
python run.py --dry-run --verbose   # 전송 없이 부서별 진행 상황과 결과 확인
python run.py                       # 디스코드로 전송 (매일 아침 8시 작업 스케줄러가 실행)
python office.py                    # 상담·사무실 화면 (http://localhost:8565)
```

## 폴더 구조

```
run.py               아침 자동 실행 진입점
office.py            화면 서버 (상담 채팅·아침 점검 실시간 이벤트 전달)
static/app.html      화면 (상담 · 사무실 · 내 도구 · 가이드)
static/office.js     2D 픽셀 사무실
run_daily.bat        작업 스케줄러가 실행하는 파일
scout/graph.py       아침 점검 LangGraph 흐름
scout/graph_chat.py  상담 채팅 LangGraph 흐름
scout/chat.py        상담팀 Gemini 연결 (없으면 단어 매칭)
scout/events.py      부서 진행 상황 이벤트 기록
scout/pipeline.py    한 번의 점검 실행 (상태 저장·전송)
scout/signals.py     작업 신호 사전 (내 대화 단어 ↔ 후보 설명 단어)
scout/profile.py     대화 기록 → 작업 신호 횟수
scout/catalog.py     후보 수집
scout/installed.py   이미 가진 스킬·플러그인
scout/recommend.py   점수와 추천 이유
scout/verify.py      검증팀 검사 (GitHub 저장소 상태)
scout/briefing.py    도구 추천 문장, 디스코드 섹션별 전송
scout/worklog.py     대화 기록 → 세션별 요청·남은 할 일·끊김·토큰·수정 파일
scout/morning.py     어제 작업·상태 점검·사용량·주간 요약 섹션
scout/guides.py      도구별 한국어 설명·사용 경우·예시 문장·추천 등급
data/                상태·캐시·실행 기록 (저장소에 올리지 않음)
```

## 아직 부족한 점

- 단어 매칭 방식이라 가끔 엉뚱한 후보가 섞입니다. 👍/👎 피드백을 받아서 고쳐 나갈 생각입니다.
- ko-skills는 화면을 브라우저에서 그리는 방식이라 아직 목록을 가져오지 못했습니다.
